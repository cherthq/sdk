# CLI beta.10 release receipt

Status: published and independently checked against the public npm registry on
October 23, 2026 at `2026-10-23T06:26:17.372Z`. The registry resolves `beta` to
`0.1.0-beta.10` and `latest` to `0.1.0-beta.6`; the registry SHA-1 and integrity
match the reviewed candidate below. A fresh-cache install from the public
registry is still pending, and published metadata does not establish a live
FaceTime call or shared-pool readiness.

beta.10 is beta.9 plus the hackathon work that was waiting on separate branches:
`chert new` (a working voice or video agent folder from the shipped starter), the
greeting on `bridge_ready`, `chert dev`'s line readiness checks before it takes a
line, time slots (`--until`, `--minutes`), every reconnect outcome reported with a
bounded attempt, and `chert context` (Chert's rules for a coding agent as one
AGENTS.md block, with `--write` and `--check`; the starters ship AGENTS.md and
CLAUDE.md). The shared-queue mode built alongside it is not in this release.

## Compared with beta.9

- Same `chert onboard`: browser sign-in and name/phone setup, automatic project
  creation, durable shared onboarding, inbound verification, one hosted outbound
  demo, busy/unqualified-line recovery and project billing links. The server
  remains authoritative for line selection, qualification, trial eligibility,
  quotas, call admission and cleanup. No demo queue is promised.
- New in `chert dev` and `chert doctor` for a project that went through
  `chert onboard` (a saved onboarding session on this computer): the control plane
  lists the allocated pool line under the project only while the allocation is
  current, with the line's own status and switch. No line listed is now
  `shared_allocation_inactive` (run `chert onboard --status`; after expiry,
  `chert onboard` requests a new allocation) instead of "ask a Chert admin to
  assign a line"; a pool line Chert keeps paused is `shared_line_paused` (Chert
  enables the pool line; nothing to press in the console) instead of the
  console's Enable calls. Every other refusal keeps its code and words; own-line
  projects are unchanged. A line held for cleanup is listed like a live one, so
  it is taken and the first call waits for the cleanup to be confirmed.
- The line readiness refusals themselves (`line_paused`, `line_unacknowledged`,
  `line_offline`, `line_draining`, `worker_unavailable`,
  `line_not_customer_decides`) are new since beta.9: beta.9 connected to a line
  that could not take calls and let every call decline.

Preserve existing `~/.chert` credentials and onboarding state when updating an
installed CLI. Do not delete resume files to recover from an uncertain request.
`--status` inspects a saved session; `--skip-demo` completes verification without
requesting the demo.

## Remaining line-dependent verification

Unchanged from beta.9: the selected lines must be qualified and enabled for shared
allocation and the hosted outbound audio/video demo, with the cloud pool, inbound
verification transport and demo infrastructure ready. Package installation does
not activate them. The shared-line words above were verified against fixtures,
not against a live allocation: no control plane served the pool routes when this
candidate was prepared.
