## Observed contracts

Chert's existing BYOR acceptance is `action=accept`, `livekit_url`, `participant_token`, `remote_participant_identity`; decline is `action=decline`. Incoming ownership identifies project, line, call, request, immutable binding/epoch/instance and generation. The authenticated connector relay replaces public webhook delivery/signing for this path. Existing HTTP receivers instead verify HMAC-SHA256 over the exact body using signature-version headers; connector credentials must never be forwarded as receiver signing credentials.

The backend's `byor-credentials.ts` validates WSS, a single roomJoin/publish/subscribe grant, separate bridge/remote identities, nbf/exp and a maximum two-hour token lifetime. It seals call credentials and reuses the Mac `start_bridge` path. It cannot verify a customer's JWT signature without their key: actual LiveKit authentication/media validation remains separate. Incoming decisions have five seconds, with four seconds for local preparation. These budgets do not define call duration. The existing connector truncates every lease to 60 seconds; the optional create-room adapter will retain that ceiling, while BYOR acceptance will explicitly select a bounded session expiry no later than the token and Chert's two-hour limit. An incompatible duration is rejected, never silently truncated.

Qualification documentation locates `/Users/garygao/demo-agent-0`. Its Python receiver (`receiver/src/chert_reference_agent`) owns durable decisions, HMAC verification, digest conflict detection, coalesced preparation, terminal suppression and room cleanup. `Service._prepare` uses existing adapter logic and `chert-byor` dispatch metadata with `demo-byor-*` identities. ContinuousDemo maintains a warm slot; HTTP lifespan starts that background work. `start()` and `shutdown()` recover/delete resources and are not non-allocating health operations. Calling this receiver or embedding its lifespan is therefore not a safe substitute for the primary callback path. Its recorded classic deployment allows audio/video, 45-second preparation, 270-second rotation and 600-second calls. The new connector does not solve its cold start or add video; its existing Python session owner needs a separate application bridge before reuse from a TypeScript module. No special connector dispatch/hook retrofit is appropriate or included here.

## Implementation boundary

One package exports a versioned TypeScript handler contract and generates a callback scaffold. New configuration v2 explicitly pins mode; init defaults to BYOR. `byor` loads only the configured absolute trusted module and requires no LiveKit master credentials, named dispatch, public URL or HTTP receiver. `create-room` retains the original adapter; legacy v1 `run` and journals retain their exact interpretation. Explicit commands reject mismatched modes before module/network/resource effects. Mode changes require fresh state and a new binding; backend mode is immutable and call ownership remains pinned.

Shared wire authentication, management, activation, receipts and reconciliation remain shared. BYOR has a distinct strict journal containing operation IDs, opaque application session references, original deadlines, authoritative outcome and application delivery/recovery evidence; no fabricated room/job ownership and no bearer credentials. Persist the intent before invoking preparation. Coalesce duplicates, cache a returned decision only in memory, reject immutable-content conflicts and never prepare again after an uncertain attempt or restart.

Handler acceptance asserts readiness and supplies existing BYOR bridge fields plus an explicit session expiry. Abort requests cancellation but does not prove settlement. A separate idempotent recovery callback receives the durable operation ID/session reference and cancellation/central terminal status; only explicit operation settlement AND application-confirmed cleanup clear resource uncertainty. Missing recovery remains a visible limitation and blocks admission. Lifecycle transport receipt, application acknowledgment, central terminal state and resource cleanup are separate facts. Persist lifecycle before transport acknowledgment; replay application delivery by stable event ID. Accepted/uncertain calls survive disconnect, revocation and replacement. Completed records remain completed during expiry/reconciliation failures.
